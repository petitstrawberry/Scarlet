# Scarlet Distribution Model

This document describes the project-centric distribution model for Scarlet OS.

## Principles

- BSP is the project directory itself — a Cargo project with boot code, linker scripts, kernel entry point
- `scarlet.toml` is the single source of truth for project configuration
- Packages are the unit of installable output — built from source or copied from prebuilt files
- Bundles are optional reusable package definitions, shared between projects via TOML includes
- All relative paths are resolved from the file they appear in
- Conflicts are resolved by declaration order: later entries win

## Terms

| Term | Meaning |
|---|---|
| Project | A directory containing `scarlet.toml`. Typically a Cargo project with kernel entry point, linker scripts, and boot code. Lives under `projects/` in the monorepo. |
| `scarlet.toml` | Project manifest. Declares kernel config, features, image composition, and optional bundle references. |
| Package | Installable output. Either built from Cargo source (`kind = "cargo"`) or copied from prebuilt files (`from`/`to`). |
| Bundle | External TOML file containing `[[packages]]` definitions. Same format as `scarlet.toml` packages section. Enables reuse across projects. |
| Image | Final bootable artifact: kernel + initramfs + rootfs + boot image. Defined in `scarlet.toml`. |
| `scarlet.lock` | Pins resolved package sources with exact git revisions. Generated by `cargo scarlet lock`. |

## scarlet.toml

The project manifest. Single file for all configuration.

### Full Schema

```toml
schema_version = 1

[project]
name = "aarch64-limine-microvm"

[kernel]
package = "scarlet"
source = "../../kernel"
target = "aarch64-unknown-none-elf"
target_json = "../../kernel/targets/aarch64-unknown-none-elf.json"

[kernel.features]
network = true
user-fpu = true
user-vector = true
hypervisor = true
limine = true
profiler = false

[modules]
"scarlet-module-prototype" = { path = "../../modules/scarlet-module-prototype", enabled = false }

[image]

[image.initramfs]
format = "newc"
output = ".scarlet/images/initramfs.cpio"

# Include packages from a bundle
[[image.initramfs.layers]]
path = "../../bundles/microvm/bundle.toml"

# Project-local packages
[[image.initramfs.packages]]
kind = "cargo"
source = "../../user/bin"
package = "user-bin"
bin = "microvm_init"
to = "/system/scarlet/bin/init"

[[image.initramfs.packages]]
from = "initramfs"
to = "/"

[image.rootfs]
format = "ext2"
output = ".scarlet/images/rootfs.ext2"

# Same bundle can be used in rootfs
[[image.rootfs.layers]]
path = "../../bundles/microvm/bundle.toml"

[[image.rootfs.packages]]
from = "prebuilt/firecracker"
to = "/usr/bin/firecracker"

[image.boot]
kind = "limine-uefi"
output = ".scarlet/images/limine-aarch64.img"
cmdline = "console=ttyAMA0"
```

### Path Resolution

All relative paths are resolved from the file they appear in:

- Paths in `scarlet.toml` → relative to `scarlet.toml` (project directory)
- Paths in bundle files → relative to the bundle file

During expansion, `cargo-scarlet` converts all paths to absolute paths relative to the project root. This means:

```
# In bundles/microvm/bundle.toml:
source = "../../user/bin"
→ resolves to: bundles/microvm/../../user/bin = user/bin
→ converted to absolute for internal use

# In projects/aarch64-microvm/scarlet.toml:
source = "../../kernel"
→ resolves to: projects/aarch64-microvm/../../kernel = kernel
→ converted to absolute for internal use
```

### Conflict Resolution

When multiple packages target the same `to` path, the last declaration wins:

1. Bundle packages (in `[[layers]]` order)
2. Project-local packages (in declaration order)

Within the same file, later `[[packages]]` entries override earlier ones.

## Packages

Packages are the unit of installable output. Two kinds:

### Cargo Build (`kind = "cargo"`)

Build a binary from a Cargo package and install it:

```toml
[[packages]]
kind = "cargo"
source = "../../user/bin"           # Path to Cargo workspace (relative to this file)
package = "user-bin"                # Cargo package name
bin = "microvm_init"                # Binary target name (optional: defaults to package default binary)
to = "/system/scarlet/bin/init"     # Install path in the image
```

### Prebuilt File Copy

Copy files directly into the image:

```toml
[[packages]]
from = "prebuilt/firecracker"       # Source path (relative to this file)
to = "/usr/bin/firecracker"         # Install path in the image
```

### Template Variables

Paths in packages support these template variables:

| Variable | Expands to |
|---|---|
| `{target_triple}` | Kernel target triple (e.g., `aarch64-unknown-none-elf`) |
| `{arch}` | Architecture shorthand (e.g., `aarch64`, `riscv64`) |

These enable architecture-independent package definitions:

```toml
# In a bundle — works for any architecture
[[packages]]
kind = "cargo"
source = "../../user/bin"
package = "user-bin"
bin = "sh"
to = "/system/scarlet/bin/sh"

[[packages]]
from = "prebuilt/{arch}/firecracker"
to = "/usr/bin/firecracker"
```

## Bundles

Bundles are external TOML files containing `[[packages]]` definitions. They share the exact same format as the packages section in `scarlet.toml`.

### Bundle File Format

```toml
# bundles/microvm/bundle.toml

# Bundles contain only [[packages]] — same format as scarlet.toml

[[packages]]
kind = "cargo"
source = "../../user/bin"
package = "user-bin"
bin = "sh"
to = "/system/scarlet/bin/sh"

[[packages]]
kind = "cargo"
source = "../../user/bin"
package = "user-bin"
bin = "hello"
to = "/system/scarlet/bin/hello"

[[packages]]
from = "prebuilt/{arch}/firecracker"
to = "/usr/bin/firecracker"
```

### Using Bundles

Reference bundles from `scarlet.toml` via `[[image.*.layers]]`:

```toml
# Use the same bundle for initramfs
[[image.initramfs.layers]]
path = "../../bundles/microvm/bundle.toml"

# And/or rootfs
[[image.rootfs.layers]]
path = "../../bundles/microvm/bundle.toml"
```

Bundles are optional. Simple projects can define all packages directly in `scarlet.toml` without any external files.

## Expansion

When `cargo-scarlet` processes `scarlet.toml`, it produces an expanded internal representation:

1. Read `scarlet.toml`
2. For each `[[image.*.layers]]`, read the bundle file
3. Resolve all relative paths from their source file to absolute paths
4. Expand template variables (`{target_triple}`, `{arch}`)
5. Merge bundle packages + project-local packages (bundle first, local after)
6. Resolve conflicts: later declarations override earlier ones

### Expanded Internal Representation

The internal form after expansion — this is what `cargo-scarlet` actually works with:

```toml
[project]
name = "aarch64-limine-microvm"

[kernel]
package = "scarlet"
source = "/absolute/path/to/kernel"
target = "aarch64-unknown-none-elf"
target_json = "/absolute/path/to/kernel/targets/aarch64-unknown-none-elf.json"

[kernel.features]
network = true
user-fpu = true
user-vector = true
hypervisor = true
limine = true
profiler = false

[image.initramfs]
format = "newc"
output = ".scarlet/images/initramfs.cpio"

# All paths resolved to absolute, templates expanded
# Bundle packages come first, project-local packages after

[[image.initramfs.packages]]
kind = "cargo"
source = "/absolute/path/to/user/bin"
package = "user-bin"
bin = "sh"
to = "/system/scarlet/bin/sh"

[[image.initramfs.packages]]
kind = "cargo"
source = "/absolute/path/to/user/bin"
package = "user-bin"

to = "/system/scarlet/bin/hello"

[[image.initramfs.packages]]

to = "/usr/bin/firecracker"

# Project-local packages (override bundle if conflict)
[[image.initramfs.packages]]
kind = "cargo"
source = "/absolute/path/to/user/bin"

bin = "microvm_init"
to = "/system/scarlet/bin/init"

[[image.initramfs.packages]]
from = "/absolute/path/to/projects/aarch64-microvm/initramfs"
to = "/"

[image.rootfs]
format = "ext2"
output = ".scarlet/images/rootfs.ext2"

[[image.rootfs.packages]]
kind = "cargo"
source = "/absolute/path/to/user/bin"
package = "user-bin"
bin = "sh"
to = "/system/scarlet/bin/sh"

[[image.rootfs.packages]]
kind = "cargo"
source = "/absolute/path/to/user/bin"
package = "user-bin"
bin = "hello"
to = "/system/scarlet/bin/hello"

[[image.rootfs.packages]]
from = "/absolute/path/to/bundles/microvm/prebuilt/aarch64/firecracker"
to = "/usr/bin/firecracker"

[[image.rootfs.packages]]
from = "/absolute/path/to/projects/aarch64-microvm/prebuilt/firecracker"
to = "/usr/bin/firecracker"

[image.boot]
kind = "limine-uefi"
output = ".scarlet/images/limine-aarch64.img"
cmdline = "console=ttyAMA0"
```

## Build Flow

### `cargo scarlet build`

1. Read `scarlet.toml`
2. Run `generate()` → creates `.scarlet/scarlet-modules/` with dynamic `Cargo.toml` based on kernel features
3. Build kernel using project's `Cargo.toml` + generated scarlet-modules
4. Build Cargo packages listed in image packages

### `cargo scarlet image`

1. Run `cargo scarlet build`
2. Expand bundles and resolve paths
3. Build initramfs: assemble files from expanded packages
4. Build rootfs: assemble files from expanded packages
5. Build boot image: package kernel + initramfs + rootfs per `[image.boot]` config

### `cargo scarlet run`

1. Run `cargo scarlet image`
2. Launch QEMU with appropriate flags

### `cargo scarlet lock`

1. Resolve all package sources
2. Pin git revisions
3. Write `scarlet.lock`

## CLI

```bash
# From a project directory:
cargo scarlet build                  # Build kernel + packages
cargo scarlet image                  # Build + generate images
cargo scarlet run                    # Build + image + launch QEMU
cargo scarlet lock                   # Resolve and pin sources

# Explicit project path:
cargo scarlet image --project projects/aarch64-microvm
cargo scarlet run --project projects/aarch64-microvm

# Profile override:
cargo scarlet image --profile debug
cargo scarlet run --profile release
```

## scarlet.lock

Pins exact source revisions. Generated by `cargo scarlet lock`.

```toml
# scarlet.lock — auto-generated, do not edit

[[package]]
name = "user-bin"
source = { path = "../../user/bin" }
resolved = { path = "../../user/bin" }

[[package]]
name = "firecracker"
source = { git = "https://github.com/firecracker-microvm/firecracker", tag = "v1.7.0" }
resolved = { git = "https://github.com/firecracker-microvm/firecracker", rev = "abc123def456" }
```

## Migration from Old Format

The old `scarlet-config.toml` format and the intermediate Yocto-style layer system are replaced by:

| Old Concept | New Location |
|---|---|
| `scarlet-config.toml` | `scarlet.toml` |
| BSP layer (`machines/`, `boot_targets/`) | Project directory itself (`Cargo.toml`, `lds/`, `src/`) |
| Distro layer (`distros/`) | `[kernel.features]` in `scarlet.toml` |
| Recipe (`recipes/`) | `[[packages]]` with `kind = "cargo"` |
| Image recipe (`images/`) | `[image.initramfs]` / `[image.rootfs]` in `scarlet.toml` |
| Package group (`packagegroups/`) | Bundles (`bundles/*/bundle.toml`) |
| `build_adapter` | Removed — project is the BSP |

## Non-Goals

- Yocto-style layer inheritance and override mechanisms
- Separate BSP layers — the project IS the BSP
- Git submodules as composition mechanism
- Requiring every app to be split into individual crates before image composition works
- Exposing low-level image-plan commands as the normal user API
- Coupling metadata to a specific directory layout beyond `scarlet.toml`

## Acceptance Criteria

- [ ] `scarlet.toml` in each project with `[kernel]`, `[image]` sections
- [ ] `cargo scarlet build` compiles kernel via project `Cargo.toml`
- [ ] `cargo scarlet image` generates initramfs, rootfs, and boot image
- [ ] `cargo scarlet run` boots the image in QEMU
- [ ] Bundles are optional — projects work without them
- [ ] Bundle packages merge correctly with project-local packages
- [ ] `scarlet.lock` records resolved git revisions
- [ ] Path resolution works correctly from both `scarlet.toml` and bundle files
- [ ] Template variables expand to correct architecture values
- [ ] No `build_adapter`, no `{project}` variable, no legacy layer code paths
