# Coordinated 1.0 release

Status: preparation in progress; the next milestone is `1.0.0-rc.1` for
Scarlet, SGFX, ScarletUI, scarlet-sdk, and the Chromebook/Adreno integration.
This document is a release checklist, not a declaration that today's APIs are stable.

The first release aligns these projects at 1.0. Subsequent versions should
follow each project's own compatibility changes. Git distribution remains
supported; publishing on crates.io is not a prerequisite.

See the [2026-09-05 migration baseline](1.0-baseline.md) for the published
revision set, CI runs, local verification, and known failures.
The [2026-09-06 handoff](2026-09-06-sgfx-scarletui-handoff.md) records subsequent
VirGL scheduling and ScarletUI frame-rejection work and its verification limits.

The [release scope and compatibility policy](1.0-scope.md) defines the target
support boundaries, package membership, and finite RC1 gates. It is not a
claim that the current APIs or runtime checks have passed release review.

## Compatibility decisions before RC1

Under [SemVer](https://semver.org/spec/v2.0.0.html), 1.0 defines the public API.
The [release scope](1.0-scope.md) selects the compatibility boundaries below.
Detailed contract decisions and implementation conformance are separate gates:

| Project | Selected boundary | Contract status / remaining evidence |
| --- | --- | --- |
| Scarlet | Stable released native/GPU ABI records and operations; source-compatible public native APIs; matched-set internal SWS wire | [Native API baseline](1.0-native-api-contract.md) records layers/features, ownership on success/error, raw mapping/control/callback safety, partial work, capabilities and GPU/SWS lifetimes. Raw operations are now unsafe, with callers adapted. Candidate dependency integration and fault/reset conformance remain; ABI/wire fields are unchanged |
| scarlet-sdk | Build tooling: `cargo-scarlet`, project/bundle manifests, source/lock resolution and image plugins | Current-behavior tooling contract recorded; scalar override fix and `--lsm` naming committed, partial `--offline` removed. 68 host tests and strict Clippy pass. Published SDK/Nix pin and candidate lock integration remain separate |
| SGFX | Coordinated Rust driver/renderer implementation with common IR/execution semantics; intended external graphics boundary is the Vulkan C ABI | The internal Rust update policy is approved in the [release scope](1.0-scope.md#compatibility-boundaries). Core/WGPU and native VirGL/ScarletUI completion are implemented. Remaining rendering/lifecycle questions are reviewed at the selected UI/GPU/SWS boundary; A618 async work is deferred. An all-exports Rust freeze is not a gate |
| ScarletUI | Source-compatible app-facing view/state/layout/scene APIs, macros, and renderer/platform extension traits | [Application/extension baseline](https://github.com/petitstrawberry/scarlet-ui/blob/main/docs/1.0-contract.md) records Scene/Window lifetime, launch/open/close, exports/features and extension responsibilities. It preserves the owning architecture and frame-failure contracts; new Scene contract tests pass. Candidate/platform conformance remains separate |
| Chromebook / Adreno (deferred) | Backend/codegen obey the SGFX execution contract and update with the Rust integration set; kernel/BSP integration is a recorded matched set | A618 implementation, submit-wire review and hardware evidence are paused at the user's request; do not resume them as the next task |

In particular, the current [SWS protocol policy](../graphics/sws-ipc-protocol.md)
allows incompatible internal wire changes. Keep that matched-set policy: a
1.0 package number does not promise old-client compatibility. Specify and
test capability-gated operations and exact frame identities under that policy.

The user approved the [SGFX #1](https://github.com/petitstrawberry/sgfx/issues/1)
architecture and internal Rust update policy on 2026-09-06. `vulkan-sgfx`, SGFX
core and selected backend/codegen link into one ICD/library; the application
graphics boundary is the Vulkan C ABI. The Rust components are migrated and
rebuilt together, including facade/direct APIs and exposed dependency types.
SGFX has no planned independently loaded Rust backend ABI or blanket 1.x source
freeze. ScarletUI can continue lowering directly into its IR; backend code owns
native budgeting, scheduling and completion.
Completing a Vulkan frontend or every future backend is not a release gate.

Package versions, Rust source compatibility, and wire/ABI version fields are
different things. Do not reset `GPU_ABI_VERSION`, `SWS_PROTOCOL_VERSION`, or
Adreno's submit-wire versions to match the package version. Keep vendored
third-party package versions unchanged, and inventory the first-party release
packages before editing their manifests.
